# Account action continuation boundary

Development checkpoint: `56aa7fe`, `codex/design-v2`. This slice protects existing actions before canonical Settings migration; it does not certify Settings presentation parity.

Cloud profile deletion sends the captured cloud ID through the actual SupabaseService `users.delete().eq('id', capturedId)` adapter. A successful database reply must not initiate logout if the Spotify principal, cloud principal, session generation, or owning component has changed. Database failure retains the confirmation and conservative partial-completion message for the same account. A stale failure must not appear in a replacement account.

An authorized logout synchronously invalidates its own session generation. Its continuation captures that new generation and permits the original identity or the fully signed-out identity, so legitimate cleanup still reaches login. Another identity/generation change rejects late navigation/error publication. Component destruction rejects subsequent continuation. An already sent deletion cannot be undone; database permissions remain authoritative.
