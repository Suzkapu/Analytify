## Workflow and safety contracts

| Trigger | Data and resulting state | Failure and recovery |
| --- | --- | --- |
| Enter Administration | Trusted admin check for the current cloud identity, followed by settings/users/runs/policy/moderation reads | An outgoing identity or invalidated session cannot grant route entry. Never start its RPC after delayed client readiness. Server permissions still apply to every privileged operation. |
| Refresh | Aggregate retained reads; retain cached data if any required read fails | Show the actual error and permit Refresh. Runtime health is intentionally absent from both composition and requests. |
| Save website settings | One write while busy; announcement and creation availability remain separate from league membership | Release busy on rejection, retain draft and allow explicit retry. Refresh currently replaces drafts; the final design must make that behavior clear. |
| Save schedule policy | Validate positive whole input and converted duration <=10080minutes; preserve selected unit. Save task/minimum/unit/availability; reload policies and users | Publish readback only after both reads succeed, replace only the saved policy and preserve another policy's draft. After an acknowledged write/read failure, explicit Refresh policy retries reads without repeating the mutation. Per-row feedback distinguishes validation, saving, saved, denied write and failed readback. |
| Save a user's settings | Address the exact user; reload inventory | Preserve cached rows on read failure. Optional schedules and feature-required tasks remain distinct; turning off optional choices must not revoke required work. |
| Run enabled tasks | One enqueue per user while pending; then refresh audit records | Audit failure must remain visible alongside acknowledged queue success. Zero queued means already queued/running, not an error. No automatic repeat enqueue. |
| Review incomplete registration | First request server review. Ineligible review never opens deletion confirmation. Cancel never deletes. Confirm sends exact reviewed Spotify identity | Server denial after review preserves the row. Database concurrency/linked-data guards remain authoritative; no frontend eligibility bypass. Native confirm remains legacy until its canonical modal is designed. |
| Save moderation decision | Address report ID, reason and distinct recipient notices; reload private inbox | Keep cached context if the dependent read fails. Appeals must remain visible before review fields. Tests use synthetic service responses; no real recipient notices. |
| Create playable demo | Trim name/default, create once while pending, then navigate to returned league ID | A false navigation result settles busy and explains that the league already exists, including its ID and Song Leagues destination. Do not report creation failure or automatically create another. Rejected navigation currently exposes its error; recovery UI and creation reuse remain design work. |
| Send test notification | Explicit admin action through authenticated function only | All tests mock the function. Never invoke a real delivery during migration verification. |

Current lifetime ownership: full-load and recent-run requests cannot publish after route destruction or a newer request. Mutation entry points also reject destroyed routes. User saves invalidate older dashboard loads, publish only the addressed user's readback and preserve other user drafts. Policy/site/moderation/queue/review/demo/notification completions check route and explicit-refresh ownership before continuing or publishing; pending registration review cannot open a late confirmation or deletion. Same-user save/queue work is mutually exclusive. Moderation and pending-deletion readbacks preserve other drafts, and demo busy state settles on supersession. Success and rejection interleavings are characterized with synthetic service responses. This does not establish live account-replacement invalidation or every browser mutation workflow. Each user save captures the activated schedule and preserves later edits across readback, accepting fresh server-owned metadata. Acknowledged saves whose private read fails expose per-user read-only recovery; duplicate Save entry cannot repeat the mutation. Repeated failures preserve recovery and drafts. Distinguish genuinely newer values from edits already matching the current server. Recovery completion cannot publish after route destruction or a newer full load, and a failed newer load retains read-only recovery. Four save services capture their primitive RPC parameters before waiting for client readiness. Twelve new cases, plus the actual mounted four-project browser workflow, protect these races. Concurrent policy updates still replace user models; future user forms need their own drafts rather than binding editable controls directly to shared inventory records.

Audit record contract: render the actual status, task label, user identity and trigger. Show requested/start/finish timestamps only when valid. Derive duration only when start/finish are valid and ordered; missing/in-progress times must not invent an elapsed duration. A warning is an actual string in `details.warnings`, including on a succeeded record; it is not a new backend status. Preserve each warning and actual error, wrap long text and keep status understandable without color. Refresh/collapse remain independent list controls; audit records are read-only. Thirty record cases protect status, semantic timestamps, invalid calendar values, missing/reversed/zero/fractional duration, warning filtering, hostile text and input replacement. Six feedback and six inventory cases cover state changes, held reads, duplicate prevention, cached failure and explicit read-only recovery; newer loads invalidate stale failures.
